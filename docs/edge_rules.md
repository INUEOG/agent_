# Edge rules

## 목적

엣지 생성은 문자열·시간의 인접성만으로 인과관계를 확정하는 단계가 아니다. 각 관계에는 생성 규칙, 근거, 증거 상태, 모순 정보를 붙이며, 요청 관계와 실제 관측 관계를 구분한다.

## 필수 엣지 메타데이터

| 필드 | 목적 |
|---|---|
| `edge_id` | 엣지 고유 ID |
| `source_id`, `target_id` | 양쪽 노드 |
| `relation_type` | 관계 의미 |
| `basis_type` | 명시적 참조, ID 일치, 명령 일치, 시간·프로세스 대조 등 |
| `supporting_evidence_ids` | 관계를 뒷받침하는 증거 |
| `evidence_status` | supported / partial / candidate / conflict / unknown |
| `rule_id`, `rule_version` | 생성 규칙의 출처와 버전 |
| `contradiction_ids` | 반대 또는 충돌 증거 |
| `observation_scope` | 관련 관측 채널과 범위 |

## 관계별 생성 기준

| 관계 | 생성 조건 | 확정에 필요한 근거 | 금지되는 추론 |
|---|---|---|---|
| `BELONGS_TO` | 이벤트-세션 소속 | 원본 session/thread ID 또는 검증된 참조 | 같은 시각이라는 이유만으로 같은 세션으로 연결 |
| `CALLS` | 메시지-도구 호출 연결 | 호출 ID·참조 또는 검증된 구조적 연결 | 요청을 실제 실행으로 승격 |
| `REQUESTS_READ` | 파일 읽기 요청 | 원본 호출/명령과 경로 | 실제 읽기 성공으로 표현 |
| `TOOL_REPORTED_READ` | 도구 출력에 파일 내용이 반환됨 | 결과와 호출·경로의 대응 | OS 수준 접근 형태까지 단정 |
| `FILE_CHANGE_OBSERVED` | 파일 변경 관측 | 전후 상태 또는 관련 OS 관측 | 시간 근접성만으로 원인 프로세스 확정 |
| `REQUESTS_CONNECTION` | 도구 호출/명령이 네트워크 대상을 지정 | 원본 인자 또는 URL | 실제 연결 성공으로 표현 |
| `NETWORK_ACTIVITY_OBSERVED` | 프로세스와 통신 행위 연결 | OS 네트워크 이벤트 또는 PCAP 근거 | 서버 처리나 데이터 수신까지 단정 |
| `SERVER_REQUEST_OBSERVED` | 대상 서버가 요청 기록 | 서버 측 접근 로그 등 | 악성 의도나 피해 확정 |
| `REQUESTS_TARGET` | 이벤트가 대상을 지정 | 원본 인자/콘텐츠와 엔터티 추출 근거 | 대상 접근·침해로 표현 |
| `POSSIBLE_ALIAS` | 두 표현이 같은 대상을 가리킬 가능성 | 설정, DNS 응답, 명시적 매핑 등 단서 | 유사 문자열이나 같은 IP만으로 엔터티 병합 |
| `CORROBORATES` | 독립 자료가 이벤트/대상을 지지함 | 관련 ID 또는 규칙에 맞는 직접 증거 연결 | 한 이벤트의 관측을 같은 이벤트의 모든 대상에 전파 |
| `CONTRADICTS` | 관측이 에이전트 기록과 모순됨 | 동일 행위·대상·시간 범위의 식별 가능한 반대 근거 | 서로 다른 범위/시각의 차이를 모순으로 단정 |

## 규칙 우선순위

1. 원본의 명시적 식별자·참조를 우선한다.
2. 엔터티별로 명령·경로·프로세스·시간·대상 식별자를 대조한다.
3. 시간은 보조 제약으로만 사용하며 단독 확정 조건으로 삼지 않는다.
4. 모순이 있으면 엣지를 삭제하거나 덮어쓰기보다 모순 증거와 상태를 보존한다.
5. 충분한 근거가 없으면 후보 엣지로 남기며, 조사 카드에서 확정 관계처럼 표현하지 않는다.

## 회귀 테스트 요건

최소한 다음 상황을 포함한다: 명시적 ID 일치, 요청만 있고 실행 없음, 타임아웃, 동일 시각의 별도 프로세스, 한 명령에 여러 대상, 실제 파일 변경, 대상 서버가 요청을 받지 않음, 독립 증거 수집 누락.
