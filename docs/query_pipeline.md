# Query pipeline

## 운영 질의 흐름

1. 조사관 질문을 입력받는다.
2. 대상 식별자, 행위 유형, 시간 범위, 세션·프로세스 등 검색 조건을 추출한다.
3. 정확 검색과 전문 검색으로 관련 이벤트를 찾는다. 벡터 검색은 표현 차이가 있을 때 선택적으로 보조한다.
4. 관련 이벤트를 시작점으로 제한된 부분 그래프를 탐색한다.
5. 관계별 근거, 모순, 관측 범위와 수집 상태를 조회한다.
6. `evidence_packet`에 관련 이벤트·엣지·원본 참조·불확실성을 정리한다.
7. 조사 카드 또는 LLM 요약을 생성한다. LLM은 근거 패킷 바깥의 사실을 추가하거나 후보 관계를 확정 관계로 바꾸지 않는다.
8. 응답에서 원본 증거와 관계 경로로 돌아갈 수 있게 한다.

## 검색 우선순위

- **정확 검색:** event/session ID, 파일 경로, IP, 도메인, URL, 명령의 정규화 값
- **전문 검색:** 프롬프트·응답·로그의 키워드
- **벡터 검색 (선택):** 동일한 개념이 다른 자연어로 표현된 경우
- **그래프 탐색:** 발견한 이벤트·엔터티 사이의 관계 경로를 제한된 깊이로 조회

벡터 검색을 정확한 ID나 IP의 기본 검색 수단으로 사용하지 않는다. 그래프 전체를 LLM에 전달하지 않고 관련 부분 그래프와 원본 근거만 패킷에 포함한다.

## 판정 불가와 모순

질문에 답할 증거가 없으면 `UNKNOWN` 또는 미확인으로 출력한다. 수집되지 않은 자료와 탐색했지만 발견되지 않은 자료를 구분한다. 상충 자료가 있으면 한쪽을 숨기지 않고 관련 근거를 병기한다.

## 결과 카드 필수 항목

- 질문에 관련된 대상/행위
- 판단한 내용과 상태
- supporting evidence 및 원본 참조
- 상충 증거와 미확인 항목
- 관계 생성 규칙과 관계가 후보인지 여부
- 다음 조사 항목(가능한 경우)
