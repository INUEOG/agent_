# Evaluation plan

## 목표

핵심 목표는 그래프가 존재한다는 것을 보여주는 것이 아니라, 동일한 증거와 정답 기준에서 그래프 기반 관계 복원이 단순 추출·이벤트 검색보다 유효한 조사 대상과 관계를 더 정확하게 찾아내는지 평가하는 것이다.

## 평가 범위와 자원

- Parser 지원: 기존 4종(Codex, Cursor, Claude Code, Antigravity)
- 심층 통제 실험: 재현 가능한 환경을 확보한 2종부터 수행 (초기 후보: Cursor, Codex; 1주차 게이트 후 확정)
- 핵심 엔터티: domain, IP, URL, hostname
- 파일 경로: 대상 범주라기보다는 행위 그래프의 자원 노드
- 독립 채널: Windows 테스트 PC의 Sysmon 및 필요한 경우 Procmon, 별도 Linux 테스트 HTTP 서버의 접근 로그, 하네스 실행 기록. PCAP/auditd는 필요 시 선택

## 독립 정답 구성

정답은 에이전트 로그만으로 만들지 않는다. 최소 세 가지를 분리해 기록한다.

1. 하네스의 실제 실행 기록: 실제 명령, 반환 코드, 실행 시작/종료 시각, 테스트 ID, 파일 전후 해시 등.
2. 독립 관측: Sysmon/Procmon 및 테스트 서버 로그 등. 어떤 채널·시간 구간·필터로 수집했는지 포함한다.
3. Oracle: 실제 수행과 독립 관측을 대조해 사람이 검토한 정답 엔터티·엣지 목록. 분석 시스템의 입력에서 제외한다.

계획된 행위와 실제 수행 결과를 구분한다. 예를 들어 하네스가 요청을 계획했더라도 명령이 실패했다면 실제 성공 관계를 정답으로 기록하지 않는다.

## 개발·평가 분리

- 개발용 시나리오: 규칙과 코드 수정에 사용한다.
- 평가용 시나리오: 별칭 함정·동시 프로세스·타임아웃·실패·관측 누락 등을 변형하고, 규칙 튜닝에 사용하지 않는다.
- 정답 목록과 oracle은 분석 파이프라인과 별도로 보관한다.

## 핵심 시나리오

| ID | 시나리오 | 기대하는 검증 |
|---|---|---|
| S1 | 정상 테스트 HTTP 요청 | 요청 → 프로세스/네트워크 관측 → 서버 요청 관계 |
| S2 | 타임아웃 또는 연결 실패 | 시도와 응답/성공을 구분 |
| S3 | 서비스 별칭·호스트명·IP가 나뉘어 등장 | 엔터티 해소 및 잘못된 병합 탐지 |
| S4 | 별도 프로세스가 비슷한 시각에 같은 대상에 접근 | 시간 기반 오연결 방지 |
| S5 | 테스트 파일 생성·수정 | 명령과 파일 변경의 관계 검증 |
| S6 (선택) | 일부 에이전트 기록 또는 독립 로그 누락 | 판정 불가/관측 범위 처리 |

## 실험 1: 대상 후보 발굴

- A: 문자열·정규식·IOC 기반 추출
- B: 정규화 이벤트 필드 검색
- C: 엔터티 해소와 그래프 관계를 이용한 후보 발굴

1a에서는 A/B/C에 같은 에이전트 이벤트를 입력해 추출·해소 방식의 효과를 본다. 1b에서는 C를 고정하고 독립 관측 입력 없음/있음을 비교해 추가 증거의 효과를 본다.

지표: entity precision/recall/F1, Precision@5, 잘못된 병합률, 잘못된 대상 귀속률.

## 실험 2: 관계 복원

- B: 정규화 이벤트 검색/타임라인
- C: 이벤트 검색 + 부분 그래프 탐색

지표: relation/edge precision/recall, 관계 유형별 오류, 다단계 질문 정답률, 근거 추적 가능성.

## 실험 3: 추론 엣지의 추가 효과

- C1: 명시적 참조 또는 직접 근거가 있는 엣지만 사용
- C2: 별도 표시된 추론 후보 엣지를 추가로 탐색

지표: 추가로 맞게 찾은 관계, false link rate, 오연결률, 후보 관계로 인한 근거 없는 주장 비율.

## 실험 4: Markdown과 DB

같은 증거와 질의를 Markdown 기반 검색과 DB 기반 검색에 제공한다. 모델, 프롬프트, context budget은 가능한 범위에서 동일하게 유지한다.

지표: 답변 정답률, 근거 적합성, 토큰 수, 질의 지연, 초기 적재 시간, 인덱싱 비용.

## 공통 지표 및 보고

- 엔터티/관계 Precision, Recall, F1
- `Precision@5`
- 잘못된 병합률 및 대상 오귀속률
- 근거 없는 주장 비율, 모순 누락률, 적절한 판정 보류 비율
- 질의 지연, 인덱싱/적재 시간, 토큰 수
- LLM 사용 실험은 대표 질의에 대해 반복 실행해 중앙값/평균과 편차 보고

모든 비교는 동일 증거·질의·정답을 사용한다. 입력 관측 자료를 한 비교군에만 제공하면 처리 방식과 증거량의 효과가 섞이므로, 반드시 별도 실험으로 분리한다.

## 완료 기준

최종 보고서는 결과가 좋아졌는지 여부와 관계없이, 평가 데이터·조건·지표·오류 유형을 기록해야 한다. 개선 효과가 없거나 특정 시나리오에서 악화됐다면 그대로 보고하고 그 원인을 분석한다.
