# Entity resolution

## 범위

핵심 평가 대상은 도메인, IP, URL, 호스트명이다. 파일 경로는 주로 행위 그래프의 자원 노드로 사용한다. 계정·조직·클라우드 리소스의 광범위한 해소는 이번 2개월 핵심 범위에서 제외한다.

## 처리 단계

1. **발견:** 원본 이벤트, 명령 인자, 도구 출력 및 관측 자료에서 후보 문자열을 추출한다.
2. **분류:** URL, hostname, domain, IP, file path 등의 유형을 구별한다.
3. **정규화:** URL의 host 추출, 도메인 대소문자/표기 정규화, IP 표기 정규화 등을 수행한다. 원본 값은 별도로 보존한다.
4. **문맥 검증:** 파일명이나 경로의 일부를 도메인으로 오인하지 않도록 URL·명령·경로 문맥을 이용한다.
5. **관계 연결:** DNS 응답, 설정, 명령 인자, HTTP 요청, 독립 관측 등 근거가 있을 때 alias/resolve 관계를 만든다.
6. **병합 또는 후보 유지:** 근거가 충분하면 동일 대상 ID를 공유할 수 있으나, 근거가 부족하거나 모순이 있으면 별도 엔터티로 두고 `POSSIBLE_ALIAS`만 기록한다.

## 하지 말아야 할 것

- 비슷한 회사명·서비스명·호스트명만으로 동일 엔터티로 확정하지 않는다.
- 같은 IP를 사용했다는 이유만으로 서로 다른 도메인을 하나로 합치지 않는다.
- 같은 이벤트에서 두 대상이 언급됐다는 이유로 두 대상에 동일한 독립 관측 근거를 전파하지 않는다.
- `.test` 등 실험용 도메인을 무조건 거부하는 TLD 허용 목록을 사용하지 않는다. 대신 문맥과 도메인 형식을 함께 검토한다.
- 파일 확장자 `.py`, `.json`, `.md` 등을 도메인으로 잘못 추출하지 않도록 한다.

## 별칭 함정 시나리오

평가 데이터에는 적어도 다음을 포함한다.

- 같은 대상을 서비스 별칭·호스트명·IP로 표현한 사례
- 이름이 비슷하지만 서로 다른 두 대상
- 같은 IP에 여러 도메인이 매핑되는 사례
- URL/명령에서만 등장한 대상과 독립 관측에서 실제 확인된 대상
- 파일 경로·파일명에서 도메인처럼 보이는 부분 문자열

## 평가 지표

- 엔터티 precision / recall / F1
- `Precision@5` (후보 우선순위 평가에 사용하는 경우)
- alias/resolve 관계 precision / recall
- 잘못된 엔터티 병합률
- 대상 귀속 오류율

정답 엔터티와 alias 정답은 개발용 시나리오와 별도로 보관하고, 후보 발굴 시스템의 검색 입력으로 제공하지 않는다.
