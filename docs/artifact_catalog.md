# Artifact catalog

## 목적

이 문서는 각 에이전트와 독립 관측 채널에서 발견할 수 있는 증거의 종류, 파서 책임, 출처 보존 기준을 관리한다. 아티팩트 위치와 내부 형식은 제품 버전·OS·설정에 따라 달라질 수 있으므로 실제 샘플과 parser locator를 기준으로 갱신한다.

## 에이전트별 카탈로그

| 에이전트 | 탐색 대상 범주 | 파서가 보존해야 할 정보 | 주의점 |
|---|---|---|---|
| Cursor | 상태 SQLite DB, 대화/트랜스크립트, 체크포인트, 도구·터미널 관련 파일 등 | 원본 파일·레코드, 고유 ID, 시각, 역할, 도구 호출·결과 | 같은 작업을 여러 저장소가 중복 기록할 수 있음. 중복 여부를 키와 내용으로 평가 |
| Codex | 세션 기록, 이벤트, 도구 호출·결과, 관련 설정·상태 | 원본 이벤트 유형, 세션/요청 ID, 명령 및 결과, 원본 참조 | 요청·실행·결과를 같은 상태로 합치지 않음 |
| Claude Code | 세션 대화 기록, 도구 사용 기록, 프로젝트 관련 설정·상태 | 세션 ID, 메시지·도구 관계, 파일/명령·결과 | 프로젝트 범위와 세션 범위를 구분 |
| Antigravity | 대화·에이전트 기록, 명령 실행 관련 기록 및 보조 상태 | 원본 ID, 시각, 행위 유형, 도구 및 결과 정보 | 모든 버전에서 동일한 아티팩트가 존재한다고 가정하지 않음 |

## 독립 관측 채널

| 채널 | 관측 예 | 가능한 주장 | 한계 |
|---|---|---|---|
| Windows Sysmon | 프로세스 생성, 설정한 경우 네트워크 연결, 파일 생성 관련 이벤트 | 이벤트에 기록된 프로세스·연결·파일 이벤트가 관측됨 | 누락 이벤트는 행위 부재를 뜻하지 않음. 설정과 수집 범위를 기록 |
| Windows Procmon | 파일 시스템·레지스트리·프로세스 활동 | 수집된 이벤트의 대상과 프로세스 동작 | 필터·수집 기간과 버퍼/로그 보존 상태에 의존 |
| Linux auditd (선택) | 설정한 시스템 호출·파일 접근 등 | 설정에 따라 기록된 OS 행위 | 규칙과 권한, 배포판 설정에 의존 |
| PCAP / 네트워크 센서 (선택) | DNS·TCP·HTTP 등 관측 가능한 패킷 | 관측된 네트워크 교환 | 암호화·패킷 손실·캡처 지점 때문에 응용 의미가 제한될 수 있음 |
| 테스트 서버 로그 | HTTP 요청, 상태 코드, 수신 시각, 테스트 리소스 변화 | 서버가 기록한 요청 또는 상태 변화 | 요청 자체가 악성 또는 피해라는 의미는 아님 |
| 실험 하네스 | 실행한 시나리오, 명령, 반환 코드, 전후 파일 해시 | 통제 실험의 실제 수행 및 기대 관계 | 계획된 작업과 실제로 성공한 작업을 구별해야 함 |

## 필수 출처 메타데이터

각 아티팩트/관측은 가능한 경우 다음을 기록한다.

- `artifact_id` 또는 `observation_id`
- `source_type` / `source_channel`
- `source_path` 또는 `source_ref`
- `collection_status`와 수집 범위
- 시각 및 `time_source`
- 원본 해시 또는 원본 참조
- 파서/수집기 버전 및 오류

## 부재와 미수집

`NOT_FOUND`, `NOT_COLLECTED`, `UNSUPPORTED`, `PARSE_ERROR`는 서로 다르다. 기록을 찾지 못했다는 사실만으로 해당 행위가 발생하지 않았다고 결론내리지 않는다.
